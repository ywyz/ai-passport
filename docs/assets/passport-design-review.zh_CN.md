## 1 发现与修订

“已修订”指设计文字与约定已改，尚不代表实现或测试通过。

| 编号 | 优先级 | 原缺口和影响 | 修订内容 | 对应验收 |
| --- | --- | --- | --- | --- |
| DR01 | 高 | 记录 ID 可任意指定，复用站点进度未按路线隔离，可能重复或串行程 | 逻辑键为账号、类型、context_id、target_id；服务端稳定 ID 映射，导游 context 为 route_id | A05、A09 |
| DR02 | 高 | 单次绑定响应丢失后无恢复定义，容易重复绑定或留下无法取回凭据 | 持久请求与短期重试证明；兑换和确认幂等，五分钟会话恢复、过期清理、撤销不可复活 | A02、A15 |
| DR03 | 高 | 连续离线操作和分页变更缺乏完整顺序及压缩条件，可能假冲突或遗漏 | 前序事件依赖、不可变变更日志、轮次上界游标、保留去重依赖、永久错误可解决 | A05 |
| DR04 | 高 | 多字段 NVS 写入、ack 后清队列、长 ID 编码未定义崩溃一致性 | 持久日志为状态来源，ack 和基础状态先可靠保存；恢复指针及 64 字节 ID 约束 | A03、A04、A05 |
| DR05 | 中 | 清单缺 file_id，接口与文件映射不一致；删字体可能让历史名称不可读 | 清单含版本内唯一 file_id；记录摘要保留所需字形或显示材料，不随缓存删除 | A03、A13 |
| DR06 | 高 | 快照只列记录文件，身份、发布对象和认证恢复边界不足，空白恢复可能孤立记录 | 快照覆盖稳定身份、发布对象、映射和一致水位；恢复重新建立认证，不自动复活旧令牌 | A06、A15、A17 |
| DR07 | 中 | 录音上限后无法短按发送，文字与动作争用上下键，菜单关闭及印章撤销含糊 | 显式发送确认状态、文字阅读模式、返回上级和关闭菜单分开、印章当前与历史区分 | A01、A10、A13 |
| DR08 | 高 | 总体 Flash 分类不是可实施分区，记录数量上限被误当容量保证 | D1 实验分区与 IDF 存储方案；隔离的只读活动与更新缓存槽、双版本算术、数量和真实空间双限制、禁止自动格式化记录 | A03、A04、A16 |

这些修订不改变用户确定的功能顺序、默认时钟首页、延后清单或 OTP 最后设计安排。OTP 仍要求独立加密备份与无原设备恢复；本次不选密码学算法。

## 2 D1 可实施边界

D1 在 `feature/passport-core` 一个功能分支内分三个增量。这里描述交接顺序，不授权本次编码。

| 增量 | 输入和产物 | 验收重点 |
| --- | --- | --- |
| D1a 网页、服务器、WebDAV | Linux＋Docker Compose；本地工作库、私有网页、测试包发布、事件接口、完整快照与恢复 | 主机及接口测试；实际 WebDAV 条件未提供时标未验证，模拟证据单列 |
| D1b 设备持久化与资源 | 新旅行界面、固定中文子集、实验分区、日志、空间预检、逐文件下载与完整校验 | 布局和格式静态检查；分配、保存、取消和掉电故障路径；无原有真实资料的实验设备 |
| D1c 配网和完整链路 | SoftAP 本地网页、实体确认绑定、HTTPS 引导、重试、离线完成记录、重连、空白恢复后的核对 | 实际手机浏览器和设备；同一事件多次重试、WebDAV 中断、旧快照与设备差异 |

D1 的下载、记录与文字查看是基础演示资料，完整铁路、导游和打卡页面仍分 D2 至 D4。不要先编码多套完整固件再合并。完成增量后应回归已有功能；只有对应 Git 授权后才提交或合入集成分支。

## 3 需要的决定与实测

| 项目 | 当前状态 | 何时处理 |
| --- | --- | --- |
| Linux＋Docker Compose | 用户已确认 | D1 本地部署资料；真实服务器部署单独授权 |
| SoftAP、SQLite、单用户、实验分区 | 设计建议，已补边界 | D1 任务确认，编码阶段做原型；若不可行修订设计 |
| 江苏测试包 | 明确虚构；真实验收省份未确定 | 不阻塞 D1，D4 数据源接入前选定 |
| 分区与存储实现 | 只核对地址、边界和容量算术 | D1 使用项目门禁验证实际表；真机测空间和掉电 |
| 字体、TLS 和运行堆 | 只有基线资料，不是新产品测量 | D1 测量，不能据此承诺最后多合一容量 |
| 实际 WebDAV | 无服务器端点或凭据，本轮未连接 | D1 A06；凭据私下配置，不写提示词 |
| 铁路时刻表、大屏、车型 | 未选定和验证真实来源 | D2 A08；不把计划数据当实时大屏 |
| 压缩音频及 AI | 未测编码、解码或服务 | D3 A10、A11；离线讲解不能静默取消 |
| OTP | 只有加密备份和遗失恢复需求 | D9 用测试种子和替代设备验收，不提前使用真实账号 |

基线默认分区表保持不变。实验方案的 5 MiB 应用包含链接字体；两个资源 FAT 槽共 2.8125 MiB、每槽 1.40625 MiB，是原始分区大小，不能全部算音频可用空间；128 KiB 记录空间也不能承诺无限历史。达到容量上限显示原因，要求同步或导出，不静默丢记录。数据迁移及刷写保存方案在真实记录使用前确定。

## 4 设计核查与交接条件

本轮设计核查包含：中英章节和标识对应、本地链接、JSON 样本解析、跨午夜和五分钟停站、路线进度 context、确认与备份状态区别、实验分区不重叠且结束于 8 MiB，以及 D1 任务覆盖 DR01 至 DR08。主机测试和现有基线门禁单独报告；不标记 A01 至 A17 的真实产品验收通过。

交给 OpenCode 的下一项任务是[提示词中的 D1](passport-travel-prompts.zh_CN.md#2-d1-共享基础实施提示词)，从精确基线建立功能分支，按 D1a 至 D1c 实现并交付证据。执行前确认修订任务与编码授权；当前保持“Codex 设计与验证，OpenCode 编码”的分工。实现后 Codex 逐项评审，问题交 OpenCode 修复，最后经批准做真机和总体测试。
