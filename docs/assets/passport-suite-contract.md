# Suite Protocol and Data Contract

## 1 Contract status and shared limits

Updated 2026-10-05, Asia/Shanghai, against `0b9e4c81ee4421c0bac39ca3561d65a8285acd4a`. Authority and U/D/C/V definitions: [PRD](passport-suite-prd.md); traceability and decisions: [prompts](passport-suite-prompts.md). SC-01 through SC-10 are D/V proposals implementing the U requirements. No custom protocol, schema, suite cache or security mechanism here is C. Limits must be reviewed and measured before implementation; changing an agreed limit requires matching both language versions, tests and capability advertisement.

All text is valid UTF-8; lengths below count encoded bytes, excluding the terminating NUL (reserve an extra byte in C). Reject malformed UTF-8, duplicate JSON keys, invalid enums, integer overflow, unexpected nesting over 8 levels and unknown required fields. Do not silently truncate authoritative fields, identifiers or ticket codes. UUIDs are lowercase canonical strings; revision integers are uint64 encoded as decimal strings in JSON to avoid browser precision loss. Hashes are SHA-256 lowercase hex. No compressed network payloads in v1; enforce caps while reading, before allocation. Content-Type and length are checked but not trusted alone.

Shared HTTPS envelope: `{api:"suite/1", request_id, operation_id?, data}`; response `{request_id,status,revision?,error?,receipt?}`. Request ID is fresh per attempt; operation ID is stable across retries of the same mutation. Different data under the same operation ID returns CONFLICT. Server scopes authorization to owner/device/resource. Lists use opaque bounded cursors, 20 records per page; never download an unbounded collection into device RAM. Ticket/task pages ≤32 KiB, settings/status ≤4 KiB. Pagination does not claim a partial dataset is a complete snapshot.

Errors carry `{code,retryable,retry_after_ms?,safe_detail}` without credentials/audio/seeds. Common codes: BAD_FORMAT, TOO_LARGE, UNSUPPORTED_VERSION, UNSUPPORTED_FIELD, UNAUTHENTICATED, FORBIDDEN, PHYSICAL_CONFIRM_REQUIRED, EXPIRED, CANCELLED, DISCONNECTED, TIME_UNTRUSTED, WIFI_AUTH, TLS_CERT, NETWORK_TIMEOUT, BUSY, NO_SPACE, CORRUPT, CONFLICT, NOT_FOUND, PROVIDER_ERROR, UNSUPPORTED_CODE. HTTP mapping: 400 format, 401 authentication, 403 permission, 404 missing, 409 conflict, 412 ETag precondition, 413 size, 429 rate/busy, 503 provider/unavailable. Retryable is an application decision, never a reason to replay a destructive action without its operation ID.

Versions: BLE transport major 1/minor 0, application `suite/1`, models `schema=1`. Reject major mismatch before any mutation. Negotiate minor/capabilities and minimum of peer limits. Ignore unknown optional additive fields only after validation; reject unknown required features. Firmware encountering a newer storage schema opens read-only/recovery mode and does not erase or downgrade it. Migration writes a new verified generation while preserving the previous one until commit.

## SC-01 Browser and BLE transport

Implements SU-02. Browser support is provisional: candidate Chrome on Windows/macOS/ChromeOS; Linux requires its own tested setup, not an assumed support label. Record OS build, browser version, adapter/driver, HTTPS origin and feature flags. Test `isSecureContext`, `navigator.bluetooth`, user-click chooser, denial/cancel, service access, notifications before writes, 20-byte fallback framing, permissions after reload, disconnect/reconnect and physical confirmation. Only then mark that exact combination supported. [Chrome official guidance](https://developer.chrome.com/docs/capabilities/bluetooth) explains secure contexts and user gestures; it is not device authentication.

If unavailable, Q-01 reviews a computer-native BLE bridge/desktop helper with an origin allowlist and explicit local consent, preserving the same authenticated application protocol. A USB computer provisioning helper is a second candidate requiring a separately designed device transport. Neither is implemented; do not substitute a phone or old SoftAP. A remote web server cannot directly operate the computer's BLE adapter.

Proposed private UUIDs (identifiers only): service `8c6f0001-6b54-4ec8-9fd1-318f72a90100`; control-write `8c6f0002-6b54-4ec8-9fd1-318f72a90100` (write with response); event `8c6f0003-6b54-4ec8-9fd1-318f72a90100` (notify); public capability `8c6f0004-6b54-4ec8-9fd1-318f72a90100` (read ≤128 bytes, also framed if necessary). One central/session; no seed read characteristic. Subscribe before HELLO. Unauthenticated commands are HELLO, AUTH_EXCHANGE, STATUS_PUBLIC and CANCEL only; public status excludes account/SSID/seeds.

Frame value length `min(ATT_MTU-3, negotiated_max, 180)` bytes; fallback 20. Fixed 12-byte little-endian header: u8 major, u8 kind (DATA=1, ACK=2, ABORT=3), u16 session tag, u32 message ID, u16 fragment index, u16 fragment count. DATA payload concatenates a logical object ≤4,096 bytes including encryption overhead; count ≤512. AUTH_EXCHANGE may be plaintext but carries no settings/seeds; all application messages thereafter are authenticated encrypted. Invalid counts/indices, session tags and excess bytes abort reassembly. One ≤4 KiB reassembly object per direction. Only one outstanding fragment, no out-of-order assembly. ACK has same identifiers/index/count and no payload; ABORT includes bounded error code.

ACK within 2 s; resend identical fragment at most twice (three total attempts), object deadline 120 s, unauthenticated handshake 60 s, inactive session expiry 120 s, physical provisioning window 180 s absolute. Duplicate fragments are acknowledged without appending twice. Last-fragment ACK confirms transport only, not authorization or durable save; final application RESULT is required. Forged/dropped transport ACK can cause denial of service but cannot authenticate a RESULT. Completed duplicate message IDs return the existing result after authenticated validation; retain 16 recent results per live session. No message-ID wrap in a session.

Encrypted record wire proposal: u8 encoding=1, u64 LE counter, ciphertext, 16-byte GCM tag; overhead 25 bytes is included in the 4,096-byte object cap. Plain HELLO/AUTH objects use encoding=0 plus bounded JSON and are never accepted as encrypted application commands. HELLO advertises transport/model versions, feature scopes, frame/object limits and random session identifiers. Associate normalized message header (major/session tag/message ID/count), direction and transcript hash with the AEAD object, not individual mutable fragment indices. AUTH results and all mutation RESULT/ERROR messages are key-confirmed/authenticated. Unauthenticated CANCEL can terminate only the current unauthenticated handshake, never a committed or authenticated operation.

Logical encrypted message: `{v:1,session_id,request_id,operation_id?,type,payload}` with type/result correlation. CANCEL targets request/operation; it is a new authenticated object when connected. Disconnect discards partial reassembly and session keys, stops candidate setup, and keeps committed data. Reconnect requires new authentication/physical window; STATUS_QUERY can recover persisted operation outcome. Never resume a ciphertext stream under old keys/counters. OTP import uses a separately confirmed capability even after reconnect.

## SC-02 Authentication, provisioning and binding

Implements SU-02/03/12. Security proposal Q-02 must receive cryptographic review before credential/seed use. Threats include nearby impersonation/replay, malicious website scripts, stolen device/storage and compromised backup server. Browser origin trust is a separate requirement: HTTPS, first-party isolated import page, strict CSP, no third-party scripts/analytics, sanitized UI text. Browser memory cannot be guaranteed wiped by JavaScript; clear references/inputs on completion/cancel, never persist plaintext seeds in localStorage, IndexedDB, service-worker caches or telemetry.

Candidate session: P-256 ECDH ephemeral keys, 32-byte random nonces, device persistent P-256 identity signing key, signed transcript (versions, roles, both ephemeral keys/nonces, device identity public key, scopes and origin), SHA-256/HKDF directional keys, AES-256-GCM with 16-byte tag. A commit/reveal of both parties' random nonces/ephemeral-key hashes precedes short-authentication-string derivation to prevent last-party SAS grinding; specify canonical transcript bytes and published negative vectors in Q-02. Display a six-digit SAS and identity fingerprint on both computer and device; user compares, then explicitly confirms on both. A name/UUID/browser grant is never proof. First pairing is physical TOFU with SAS, not manufacturer attestation; retain the approved device public-key fingerprint in the browser/owner record. Subsequent identity change blocks and requires explicit re-pair review. Device validates browser session by the same confirmed transcript and owner-binding token; bearer ownership alone cannot replace physical first-pair confirmation. Limit three failed confirmation attempts per physical window and close on failure. No secrets before mutual key confirmation.

AEAD nonce: per-direction four-byte session-random prefix plus u64 monotonic counter; directions have different keys. Header/roles/version/session/transcript hash are associated data. Reuse neither counter nor key across restart; retransmit only identical ciphertext for a duplicate message. Authentication failure immediately destroys session. SAS probability and physical key protection remain unverified; do not label this production-safe before review and measurements.

State: CLOSED → physical menu confirmation → WINDOW_OPEN → AUTHENTICATING → AUTHENTICATED_SETTINGS → CANDIDATE_TEST → COMMITTED, or CANCELLED/FAILED → previous COMMITTED/CLOSED. Countdown is not extended by traffic. WIFI_STAGE contains operation ID, SSID ≤32 raw bytes encoded Base64, password ≤64 bytes (supported WPA2/WPA3/open-network policy Q-03), server origin ≤256 bytes and owner-binding token ≤512 bytes. Validate inputs without exposing passwords. WIFI_TEST timeout 45 s including association/DHCP/validated server health; CANCEL restores old network. Keep candidate in volatile memory until successful server TLS test and explicit WIFI_COMMIT. Persist new configuration in a verified transaction; power loss/cancel/wrong password/timeout/disconnect before commit leaves old configuration active. Do not clear old credentials on auth failures.

Commands: WIFI_STAGE/WIFI_TEST/WIFI_COMMIT/WIFI_CANCEL; BIND_PREPARE/BIND_COMMIT/BIND_STATUS/REVOKE; SETTINGS_PATCH/STATUS_QUERY. Stage response is not a commit. BIND_PREPARE browser obtains owner-authorized one-use token (180 s), bound to device identity fingerprint, server origin and operation ID. Device verifies server via TLS, proves possession of identity private key over server nonce and redeems token. Server durably records a unique `(owner_id,device_id)` binding plus operation result before issuing scoped device credential; repeating the same token/operation returns the same binding, different owner fails CONFLICT. Token expiry returns EXPIRED; no automatic transfer. Lost responses are resolved with signed BIND_STATUS. Normal BLE settings cannot replace server identity or take ownership without fresh physical authorization.

Revocation: owner can revoke through independent website login even when device offline; server denies new device requests immediately, invalidates refresh credential and records revocation epoch. Device marks unbound and removes server credentials after validated rejection/explicit local confirmation; retained local tickets/tasks/OTP are not silently erased. Offline cached viewing is distinct from revoked online access. Rotate credentials without changing owner using versioned transaction; never log them. Nextcloud credentials reside in server secret storage, never generic BLE settings.

## SC-03 Time, TLS and Wi-Fi reconnect

Implements SU-03/09/12. Never disable certificate chain, hostname or validity checks; select CA bundle/private CA explicitly per approved server. ESP-IDF 5.5.3 supports configured trust anchors through [ESP-TLS](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/protocols/esp_tls.html). A browser-provided wall clock or unauthenticated SNTP value is only a hint, not OTP trust.

Q-04 proposal for first TLS bootstrap: firmware carries an independently distributed time-service signing public key. Send a fresh 32-byte boot nonce to a bootstrap endpoint without credentials; accept only a signed `{schema,nonce,utc,uncertainty,key_id}` matching the nonce, signature, sane firmware minimum date and ≤2 s request RTT. Plain transport may carry this public signed object; it neither authenticates ordinary services nor relaxes TLS. Apply time only after signature validation, then perform full TLS verification and binding. Pinned-key rotation and unavailable bootstrap recovery must be reviewed; user changes to server URL cannot replace this trust root through ordinary settings. On subsequent boots still obtain fresh time; persisted last UTC is an anti-rollback bound, not elapsed time through power-off. Signed time + elapsed monotonic time establishes a running trust estimate.

Time state `{UNKNOWN,HINT,TRUSTED,STALE}`, with source, synchronized UTC, monotonic reference, uncertainty_ms and persisted lower bound. Wall-clock rollback or unexpected >2 s jump makes OTP unavailable pending validated resync. Proposal: resync every 6 h; uncertainty increases using measured oscillator drift and sleep behavior; OTP allowed only with uncertainty ≤2 s and sync age ≤24 h. If drift has not been measured, offline trust is not established merely by these numbers. Power-on reset returns UNKNOWN, because the current board contract offers no battery-backed calendar clock guarantee; [IDF system time](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/system/system_time.html) describes reset/sleep timer behavior. Home may show explicitly uncertain time; OTP displays no code in UNKNOWN/HINT/STALE.

Reconnect: supervisor states DISABLED/CONNECTING/ONLINE/BACKOFF/AUTH_FAILED/REVOKED. Association deadline 20 s, request connect 10 s, idle read 10 s, ordinary request total 30 s. Backoff 1/2/4/8/16/30 s with ±20% jitter; after five failures wait 5 min or user refresh. Credential/auth/certificate failure stops blind retries and shows actionable reason. Resume durable operations only after authenticated connectivity/time. Schedule BLE provisioning separately from bulk ticket downloads and speech; follow [IDF 5.5.3 coexistence](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-guides/coexist.html), then measure actual radio overlap. No performance guarantee is inferred from SDK support.

## SC-04 Page and background state ownership

Implements SU-04. Page reducer consumes `{page_generation,gesture_id,request_id,event,data_handle}`; generation is advanced at transition start. ENTERING → READY → LEAVING → STOPPED; no reentry until previous stop acknowledgement. Long-gesture consumption occurs before navigation. A fresh PRESS creates the next epoch; stale CLICK/DOUBLE is ignored, including after page transition. Input overflow latches consumed LONG and cancellation independently; movement may be coalesced. Host tests must inject PRESS/LONG/CLICK ordering, duplicate LONG, missing events, rapid double clicks and saturated queues.

Workers receive cancellation tokens, never page pointers; completion models refer to stable storage/model handles. UI receives only matching generation/request results. Background sync has its own durable operation ID and survives page exit; notifications unsubscribe on exit, and completion does not resurrect a page. Audio/page timers stop within proposed 2 s deadline; if BSP PCM blocking exceeds it, retain owner/object state and show stop retry. A stop timeout is not permission to free resources still in use. Any reusable timeout/cancel API extension to BSP requires its own public contract, fault injection and measured stop acceptance.

Only a single audio arbiter configures/reads/writes/sleeps the codec. Background synchronization writes models through the storage owner, not LVGL. UI owner does rendering; any non-LVGL task using LVGL holds `bsp_lvgl_lock()`. Never hold the UI lock across network/Flash/PCM I/O. Journal queue max 64 completion intents; input depth 16; event/model queue depth 8 with newest-status coalescing, but durable operation receipts cannot be dropped silently. These counts are provisional budgets.

## SC-05 Ticket model, publication and original codes

Implements SU-05/06. Common record: `{schema:1,id,revision,type,title,source,review,updated_at,fields,missing,code,tombstone}`. ID is server-issued stable UUID, never reconstructed from title/date/order. Type train/flight/performance/other. `source={kind:manual|paste|issuer,reference?,observed_at}`; human corrections retain provenance. `review={state:draft|reviewed|published,reviewed_at?,reviewer_id?}`; device receives published only. Each field may be null, with `missing[field]=not_provided|uncertain|not_applicable|redacted`; do not substitute zero/empty-seat defaults. Title ≤256 bytes, each scalar text ≤256 bytes, instructions ≤2,048 bytes; whole metadata ≤8 KiB; maximum 100 locally cached tickets and metadata total ≤800 KiB.

Time value: `{kind:instant|date|range,local_date,local_time?,tzid?,utc?,end?}`. Instants require full ISO 8601 local date/time, IANA zone and explicit UTC offset/UTC instant; reject unresolved DST ambiguity, never infer arrival date from departure time. Date-only stays date-only with venue timezone context, not midnight UTC. Display origin/destination local zones; validity range has inclusive/exclusive boundary semantics explicitly (`start_inclusive=true,end_inclusive=false`). `updated_at` is UTC with offset. Stable revision increases on every published correction; deletions publish tombstones.

| Type | fields (display when source provides them) |
| --- | --- |
| train | service_number, travel_date, boarding_station, alighting_station, origin_station separately, departure, arrival, carriage, seat, seat_kind (assigned/unreserved/standing), class |
| flight | flight_number, departure_airport/terminal, arrival_airport/terminal, departure, arrival, boarding_at, gate, seat; gate/boarding source and observed_at separately |
| performance | event_name, venue, address, session_at, area, row, seat, standing flag |
| other | name, ticket_kind, validity, venue/address, entry_instructions, source seat |

Website messages/endpoints: POST `/suite/v1/tickets/drafts` manual/paste, PATCH draft with If-Match revision, POST `/{id}/review`, POST `/{id}/publish` with operation ID and reviewed revision. No publication of unreviewed changes. GET `/suite/v1/tickets/snapshot?cursor=...` returns manifest revision and paginated IDs/hashes; GET `/{id}/revisions/{revision}` and `/code` return bounded immutable objects. Device pins one manifest revision across pages; if expired restart snapshot, not mix generations. Download to scratch storage, validate schema/length/hash/provenance and all required objects, then atomic active-manifest commit. Any error/power cut/full space leaves old active revision. Local cache clear is separate from server deletion; deletion requires reviewed tombstone acknowledgement. Browsing/code opening emits no redemption or used status.

Code object: `{origin:issuer,kind:qr|barcode|image,mode:static|dynamic|identity_bound,payload_encoding:bytes|utf8,original_payload?,original_image?,symbology?,valid_from?,expires_at?,source_reference,sha256,display_status,reason?}`. Only issuer-original bytes or verified issuer original image; never synthesize admission data from order, seat or train number. Re-encoding exact issuer QR bytes is allowed only with verified semantics; otherwise use original image. Accepted payload ≤1,024 bytes, original image ≤64 KiB encoded and decoded dimensions ≤512 × 512; stream decode/one-bit cache, not a full RGB framebuffer. Aggregate cached code objects ≤1 MiB. Reject unknown/dynamic/identity-bound offline validity instead of promising entry; dynamic support requires Q-06 issuer-specific refresh/auth rules and online expiry checks. Detail remains available with code reason absent/expired/unsupported/too_dense/unverified.

Rendering: no unrelated animation; 216 × 216 square within 240 × 320 rounded panel. For QR modules N, reserve at least four modules of white quiet zone per side; integer scale `s=floor(216/(N+8))`, proposed minimum s=3 → N≤61. Reject if not fitting; no interpolation, clipped quiet zone or fake successful scan. [DENSO guidance](https://www.qrcode.com/en/howto/code.html) specifies the four-module margin. Barcode minimum module width/quiet zones depend on symbology and must be separately specified/validated; do not rotate/resize arbitrarily to fit. Images lacking known geometry/quiet zone are unverified and cannot pass code acceptance. Brightness/contrast and actual reader scans are SA-09 separately from metadata, encode and layout host tests. A screen scan does not prove issuer admission rules or replace official identity credentials.

## SC-06 Nextcloud CalDAV and offline completion

Implements SU-07/08. Server adapter, not device, speaks CalDAV. Discover authenticated principal/current-user-principal and calendar-home-set, PROPFIND collections and supported-calendar-component-set for VTODO, then calendar-query REPORT and calendar-multiget as needed. Preserve collection href/credential account and ETag. List selection is stored as explicit collection IDs, not display names. [RFC 4791](https://www.rfc-editor.org/rfc/rfc4791) defines discovery/reporting; [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545) defines VTODO/time values. [Nextcloud Tasks](https://github.com/nextcloud/tasks) is the real integration target, whose deployed Nextcloud/Tasks versions must be recorded in Q-07. WebDAV backup files cannot substitute for CalDAV operations.

Model: `{schema:1,account_id,collection_id,href,uid,recurrence_id?,etag,summary,status,percent_complete,completed_at?,due,note,modified_at?,snapshot_revision,downloaded_at}`. Identity is `(account_id,collection_id,uid,recurrence_id)`; href is a locator, UID alone is not globally unique. Recurrence handling is gated by real-version testing; do not complete an entire recurring series through a simplified item. Keep original VCALENDAR/VTODO server-side, preserving unknown properties, alarms, recurrence/subtask relations and folding. Unsupported instances/shared lists are labeled read-only until verified.

`due={kind:none|date|zoned|utc|floating,value,tzid?}`: date-only means an all-day date, no fabricated time; none sorts after dated items; floating retains no timezone and explicit label until policy reviewed. Resolve TZID/VTIMEZONE server-side, return both original and normalized display value, never discard source zone. Summary ≤512 bytes; preview note ≤4,096 bytes at a valid UTF-8 boundary with `note_truncated=true,original_bytes` if longer; original preserved at server. Device details page notes, not one oversized label. Task record ≤8 KiB, page ≤32 KiB, cache ≤200 items/1 MiB; collection list ≤20/8 KiB. Limit overflow is explicit with selected/filter/pagination guidance, not silent missing tasks. Cache stale after 24 h; reading cache stays possible; offline completion carries old ETag and may conflict.

Device API: GET `/suite/v1/task-collections`, PUT `/task-selection` with revision, GET `/tasks/snapshot`, POST `/task-completions`, GET `/operations/{operation_id}`. Refresh states FETCHING/READY/EMPTY/STALE/AUTH_FAILED/READ_ONLY; server connection and device downloaded snapshot are separate receipts. 401/403 from Nextcloud halts retries and asks to repair authentication privately; no password in device errors.

Completion intent `{operation_id,identity,base_etag,desired:completed,created_at?,device_sequence,payload_hash}`. Durable device journal admission precedes optimistic Pending; list badge is pending, not remote success. Queue ≤64; full/no-space reports Not saved and leaves original status. State NEW → LOCAL_DURABLE → SERVER_DURABLE → REMOTE_APPLYING → SUCCEEDED or CONFLICT/FAILED; reboot replays same operation ID. Server stores operation and idempotency result transactionally before SERVER_DURABLE. Completion application: fetch current resource, compare exact base ETag, alter only selected VTODO STATUS=COMPLETED/PERCENT-COMPLETE=100/COMPLETED trusted UTC and necessary modification metadata, preserve all other components/properties; PUT with `If-Match` ETag. No unconditional PUT. 412/changed ETag enters CONFLICT, even if some unrelated field changed; show refreshed remote text and request explicit new confirmation/new operation ID with current ETag. Missing resource returns NOT_FOUND, never recreates it.

If PUT succeeded but response lost, fetch resource: if target is completed and recorded intent has no contrary newer state, report achieved without another write; if changed/ambiguous, conflict review. Do not claim exactly-once remote execution without server evidence. Same operation+hash returns stored result, same ID/different hash conflicts. Transient retries: 2/5/15/60/300 s with jitter, max five per session then visibly paused until reconnect/manual refresh; journal retained across reboot. Never retry auth/precondition failure blindly. Do not overwrite a remote reopened task; reopening from device is not implemented pending Q-07. Cancel before remote application records a durable cancelled intent; after application cancellation is too late and cannot imply reopening. Snapshot updates preserve unresolved intents independently and do not clear queue on cache replacement.

SA-10 uses simulated discovery/ETags/power cuts; SA-11 separately requires actual Nextcloud discovery/list reads; SA-12 separately requires real completion, reboot/offline replay and concurrent webpage edits. A mock success cannot satisfy either real acceptance.

## SC-07 Home scene and weather

Implements SU-09. Home becomes boot default once ST-03 is accepted. Procedural three-body-inspired visualization is illustrative, not an astronomical prediction: three normalized masses/positions, softened inverse-square force, fixed-step integrator at most 20 ms simulated step, at most four integration steps per rendered frame, capped coordinates/speeds, deterministic seed/reset when divergence occurs. Host tests check boundedness/determinism and no NaN. Render at most 10 FPS, pause when hidden; update clock text at 1 Hz, no whole-screen RGB framebuffer. Power/visual smoothness are measured, not claimed from these limits.

Weather `{schema,city_id,city_label,tzid,observed_at,fetched_at,expires_at,temperature_c,condition,provider,revision}`; label ≤128 bytes, object ≤4 KiB. Website selects explicit city/zone, no implicit GPS/phone location. Provider and attribution/license Q-08. Proposed refresh 30 min, stale after 2 h or provider expiry sooner; failure retains last record with age, empty shows Unavailable. Clock and weather trust/freshness are separate. A weather error must never block launcher, local trusted clock, wallet/tasks or OTP. Weather HTTP uses SC-03 deadlines and background owner; frame/clock timers cannot perform network I/O.

## SC-08 Voice translation and fonts

Implements SU-10/11. Format proposal: PCM signed 16-bit little-endian, 16,000 Hz, mono, no WAV header on streaming chunks. 10 s maximum =320,000 bytes; minimum 0.3 s. Click OK starts only after ONLINE, trusted TLS and server session admission; click OK again finalizes. UP/long OK cancel. Direction zh-CN→en or en→zh-CN, no automatic detection. Chunk 1,024 bytes (512 samples/32 ms), eight-chunk RAM ring =8 KiB plus capture/playback scratch ≤4 KiB. Never use the demo's 96 KB whole-clip allocation or keep 320 KB in RAM. Server temporarily spools bounded audio; no device audio Flash history.

POST `/suite/v1/translations` creates job `{operation_id,source_lang,target_lang,format,limit_bytes}`; PUT `/{job}/audio/{sequence}` has ≤8 KiB body and chunk SHA-256, ordered acknowledged offsets; POST `/{job}/finish` contains total bytes/hash. Duplicate same sequence/hash acknowledges same offset; different bytes conflicts. Stop upload on ring overflow/backpressure lasting >250 ms: abort whole job with BUSY, do not drop samples and pretend full recording. Capture must drain PCM continuously within budget; if HTTP batching cannot keep up, reduce approved recording ceiling or review compressed codec, not unbounded buffers. Server capture/job absolute lifetime 120 s; partial uploads never trigger billed recognition automatically. Cancel DELETE `/{job}` is idempotent, but already completed provider billing is not promised reversible.

State READY → RECORDING/UPLOADING → FINALIZING → RECOGNIZING → TRANSLATING → SYNTHESIZING → RESULT → PLAYING, or CANCELLED/ERROR → READY. UP/long OK cancel in every busy state, generation invalidates late results. Deadlines: upload connect 10 s, idle 5 s, recording 10 s; recognition 20 s, translation 15 s, synthesis 20 s, post-record pipeline total 60 s. Return monotonic progress state without secrets. Retry only status/idempotent upload within same job; no automatic new billed job after ambiguous finish. Offline disallows new capture; mid-capture disconnect cancels with clear error, no silent offline translation claim.

Result `{job_id,source_text,target_text,source_lang,target_lang,provider_states,audio?,expires_at}`. Each text ≤2,048 bytes and ≤512 Unicode scalar values, validated at character boundary. If exceeded return TOO_LARGE and preserve any clearly labeled valid source; do not invent summary as a translation. Source and translation have separate labeled scroll sections. Synthesis failure may leave usable text with Voice unavailable. Playback PCM 16 kHz/16-bit/mono, ≤15 s/480,000 bytes streamed with same bounded ring; OK/UP/long OK stops via audio owner, stop target ≤2 s subject to measured BSP latency. Audio URL is authorized and expires in 5 min, not a public reusable link.

Adapter interface Q-09: recognize bounded audio→source text; translate explicit pair→target text; synthesize text→bounded audio. Select provider/API version, region, streaming support, limits, billing cap, cancellation semantics, data retention and licensing before real adapter work. Mock adapters return `provider_mode=mock`; SA-14 tests mocks/limits, SA-15 requires real Chinese→English and English→Chinese speech/text/playback. Never call a fixture real service acceptance.

Retention proposal: device audio only volatile, erased/freed on finish/cancel/error; text only current page session, wiped on exit/reboot, no history. Server raw/synthesized temporary audio deleted on cancellation or successful retrieval, hard TTL 5 min and orphan cleanup on restart; source/translation payloads excluded from request logs/backups. Provider deletion/retention cannot be assumed: Q-09 must approve policy or block actual user audio. Keep anonymous duration/error metrics only if separately approved.

Chinese font plan: licensed pinned CJK font subset for all static UI plus declared dynamic inventory (candidate ASCII/punctuation/CJK Unified Ideographs U+4E00–U+9FFF, subject to Flash fit Q-05); 16 px body and 20 px headings. Explicitly select fonts on labels, menus, popups and states. Server reports unsupported code points; show an intentional Unsupported character indication preserving original in website, never silently erase characters or disable missing-glyph placeholders. Validate per-code-point coverage, known-missing negative cases, UTF-8 safe wrapping/truncation, converter/license and [font integration](../development/engineering/lvgl-chinese-fonts.md). Static subset alone does not cover arbitrary names/translations. If full declared inventory does not fit, narrow it visibly or review another bounded font delivery design before claiming support. SA-16 separately observes every page, long content and mixed Chinese/English on hardware.

## SC-09 OTP vault, permission and recovery

Implements SU-12/13. Detailed design is complete for review this round; all mechanisms D/V. Candidate TOTP: T0=0, counter=floor(UTC/period), HMAC SHA-1/SHA-256/SHA-512 with dynamic truncation and decimal zero-padding; 6 or 8 digits, periods 30 or 60 s, defaults SHA-1/6/30. No HOTP in v1; reject unsupported type/algorithm/period/digits rather than silently substitute. [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238) supplies the algorithm and public vectors. URI parsing follows the [Google Key URI format](https://github.com/google/google-authenticator/wiki/Key-Uri-Format), not an assertion that every authenticator supports all parameters. Verify each fictional account against independent vectors, including leading zero and period boundary; actual account parameter compatibility Q-10. No real seeds requested or stored this round.

Browser locally parses `otpauth://totp/...` or a local QR image, decodes Base32 and percent escapes, validates issuer label/query agreement, refuses duplicate/conflicting parameters and displays issuer/account/algorithm/digits/period before import. URI ≤2,048 bytes, decoded secret 10–64 bytes, issuer/account each ≤128 bytes, max 32 accounts. No URI in URL/network/logs. Vault record `{schema,id,revision,issuer,account,algorithm,digits,period,encrypted_secret,created_at?,deleted}`; random stable ID, duplicate import operation idempotent by operation ID, matching labels are not proof of same seed. Metadata visibility itself requires unlocked OTP capability.

Ordinary AUTHENTICATED_SETTINGS grants no OTP rights. Local unlocked vault + fresh device menu confirmation creates OTP_IMPORT capability bound to session transcript, expires 60 s, permits one reviewed account. Commands OTP_IMPORT_PREPARE (metadata only), OTP_IMPORT_COMMIT (encrypted seed), OTP_IMPORT_STATUS, OTP_DELETE, OTP_BACKUP_OPEN/CHUNK/FINISH and OTP_RESTORE_PREPARE/COMMIT exist only within separately scoped one-use capabilities. For an empty vault, physically confirmed OTP setup grants metadata-only PREPARE; no existing unlock is required, but seed COMMIT remains blocked until PIN setup and the one-use capability. First import sets a local PIN and recovery policy before durable secret commit; user verifies fictional vector display. Disconnect/cancel before commit wipes staged secret; lost commit response queries operation status under a new authorized session, never repeats a blind seed insert. No generic settings RPC, ticket export or status response contains seed bytes. No normal read/export command for plaintext seeds.

Local unlock proposal: eight-digit PIN entered with UP/DOWN selecting one digit and OK advancing; digit is briefly shown then masked, long OK cancels. PBKDF2-HMAC-SHA256 with per-vault ≥16-byte salt, candidate 600,000 iterations derives key to unwrap random 256-bit data key; measure on C3 before selecting work factor/UI latency (Q-10). Store authenticated AES-256-GCM encrypted secrets with unique 96-bit nonce, account ID/schema/revision as associated data. Persist failed-attempt count before reply; after five failures lock 5 min, exponential delay to 1 h; reboot must not reset counters or bypass delay (if time untrusted require authenticated recovery/unlock policy). Idle 60 s or OTP-page exit/boot locks, wipes decrypted keys/seeds/code labels, pauses display. Time outside SC-03 TRUSTED bounds shows no code. Offline trusted-time operation does not require server login.

PIN entropy is limited; software rate limits do not defeat copied-Flash brute force or malicious firmware. Production seed use is blocked by Q-10 until physical-storage/key protection, secure boot/Flash/NVS encryption and lockout design are reviewed. ESP-IDF [Flash encryption 5.5.3](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/security/flash-encryption.html) involves device security configuration; no eFuse writes or irreversible enabling is authorized by this contract. Device identity key/storage protection shares this review. Public vectors and fictional accounts can test software without claiming physical attack resistance.

Deletion requires local unlock and explicit physical confirmation; tombstone/manifest commit first, remove encrypted record, clear working buffers, invalidate capabilities. Flash wear-leveling may retain old ciphertext; do not promise forensic erasure. Old backups can still recover deleted accounts; display that warning and allow explicit backup-version purge under independent authorization. Upgrade: migration preserves vault UUID/data key wraps and verified encrypted records; never factory-reset to fix schema errors. Export encrypted recovery and check compatibility before an explicitly authorized layout-changing flash. Full merged image at 0x0 can overwrite stored regions; segmented preservation requires layout/target review, not an assumed guarantee.

Independent recovery proposal: computer generates 32 random bytes as recovery key with Web Crypto, user saves it outside the original device and server (offline print/file/password-manager record accessible without this OTP). A separate OTP_BACKUP capability creates an AES-256-GCM recovery archive, encrypted before upload, with recovery key wrapping an independent archive data key; entropy/salt/nonce and schema/KDF/AEAD IDs are in authenticated header, account records inside ciphertext. Transfer recovery key only within reviewed protected BLE; do not persist it on device or server. Container ≤64 KiB, chunk ≤1 KiB, stream encrypted chunks; ciphertext-only endpoint/storage namespace `/otp-backups` with separate permission, excluded from ordinary ticket exports/WebDAV trees. Browser may download encrypted archive offline; clear temporary key references after confirmation. Q-10 must pin exact container bytes, nonce allocation and known-answer/wrong-key tests before implementation.

Restore without original device: independent website recovery codes/second authenticator or offline archive retrieval → offline key access → browser local authenticated decrypt → inspect metadata → new device verified session + local unlock/physical restore capability → bounded staged records → checksum/schema verification → atomic vault commit. Wrong key/corrupt/archive-too-new fails without modifying old vault. Backup access cannot depend solely on the original device's generated OTP. Encrypted OTP backup completion has its own receipt and key-possession/recovery test; a server ciphertext receipt alone does not prove recoverability. Web Crypto supplies primitives, not this product's protocol correctness; see [W3C Web Crypto](https://www.w3.org/TR/webcrypto/).

## SC-10 Resource budgets and durable preservation

Implements SU-14/15. ESP32-C3, 8 MB Flash, no PSRAM, IDF 5.5.3. Upstream [default partitions](../../partitions.csv) stay NVS/PHY/factory. No 5 MiB app assumption, no dual resource slots. Application partition design Q-05 must allocate cache/journal/vault/metadata from measured image and data needs and define migration/flash consequences before persistent implementation; the default 24 KiB NVS cannot hold the proposed caches. Do not alter upstream template contracts to force application partitions.

| Component | D/V initial ceiling / measurement gate |
| --- | --- |
| App code/RO data excluding fonts | Target ≤3 MiB, measure actual IDF size; not a reserved partition |
| Fonts | Candidate ≤2 MiB Flash, ≤16 KiB dynamic glyph/cache RAM; dynamic coverage may force redesign |
| Ticket metadata/codes | ≤800 KiB metadata +1 MiB codes; decoding scratch ≤16 KiB; no full-image RAM decode |
| Tasks/journal/settings/vault | Tasks ≤1 MiB, journal ≤64 KiB, settings/operation records ≤64 KiB, OTP ≤64 KiB; encryption/tag overhead measured |
| Atomic save scratch | At least largest replaceable record plus manifest/journal commit reserve; whole-snapshot doubling not assumed; finalize Flash allocation after write-amplification tests |
| Audio | 8 KiB ring +≤4 KiB scratch, DMA separately measured; no whole recording RAM allocation |
| LVGL/display | Candidate LVGL 32 KiB +≤24 KiB DMA/draw buffers; inspect real BSP allocation and map, cap object count; no 153,600-byte RGB565 full frame |
| BLE/Wi-Fi/TLS/crypto | Reserve candidate combined peak ≤140 KiB; measure minimum heap/largest internal/DMA block with actual authentication and TLS; not additive guarantees |
| Task stacks | UI/input 4 KiB, sync 6 KiB, storage 4 KiB, audio 4 KiB, application crypto 6 KiB; IDF/NimBLE/LVGL stacks measured separately, initial total stack target ≤48 KiB |
| Safety margin | Minimum free internal heap ≥40 KiB and largest block ≥16 KiB at measured peak; no allocation may rely only on total heap |

The table is a set of proposed ceilings, not proof that summing them fits available RAM/Flash. ST-01 instruments baseline and concurrent worst cases; run `idf.py size`, size-components, size-files, MAP analysis, `heap_caps_get_minimum_free_size`, largest-free-block/DMA checks and stack high-water marks. Measure font drawing, QR decoding, encrypted BLE, Wi-Fi TLS handshakes, speech capture/playback and power-cut storage together where scheduled. Runtime admission rejects jobs without reserve. ST-06 verifies 100 navigation/cancel cycles and 24 h mixed operation, leak trend, watchdog and heap/stack margins. Cache quotas must include record headers, AEAD tags, journal, fragmentation and scratch; reject updates with NO_SPACE rather than deleting active data.

Device save: storage-owner journal with schema/sequence/length/hash (CRC for torn-write detection, AEAD for secret integrity), immutable records → verified manifest → atomic active pointer. Power loss before commit retains previous generation; after commit recovers new generation; corrupted staging ignored/quarantined. Pending completion intents have a separate durable journal and are never removed by snapshot cleanup. Garbage collect only unreachable committed objects after reserve checks. Exact backend (NVS blobs/filesystem) and transaction primitive depend on Q-05; do not claim filesystem rename alone is power-safe without flush/commit tests.

Receipts: LOCAL_SAVED means device commit verified; SERVER_RECEIVED means server database/file and outgoing backup queue durably committed; WEBDAV_BACKED_UP means backup object, manifest and hash have been uploaded/read-verified. Each includes resource/revision/hash/time and operation ID, displayed separately. Server 202 may mean accepted durable queue, never Nextcloud completed/WebDAV finished. Backup failure keeps reliable server data and queued retry; full server disk returns NO_SPACE before success. Ordinary WebDAV contains tickets/settings/task snapshots/journal as allowed, no plaintext credentials or OTP. OTP ciphertext is separately permissioned/namespaced and independently recoverable.

Empty-server recovery: owner authenticates without original OTP, selects immutable verified WebDAV backup manifest, verifies version/hashes, restores records and operation ledger in staging, commits new server generation; revoked device credentials are not resurrected, bindings need reconfirmation. Reconcile task intents with live CalDAV/ETags before replay; backups are not authoritative newer task edits. Devices holding newer local revisions offer reviewed export/reconciliation, never blindly upload stale snapshots over restored state. OTP restores through SC-09 only, not general backup. If no backup exists, declare unrecoverable server records and offer existing approved device export; do not promise reconstruction from metadata alone. SA-21 covers disk-full/torn writes/corrupt backups and recovery with original device unavailable.
